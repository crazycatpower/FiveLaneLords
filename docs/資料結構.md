# 資料結構（2026-11-03）

## 冒險內容的唯一來源

- `campaign_catalog.gd`：章節、關卡設定、玩家／敵方牌組、初始建築、地圖座標、通關獎勵。每關採多行欄位方便審查差異。
- `campaign_story_data.gd`：以固定關卡 ID 為 key 的 `SCENES` 常量；`dialogue()` 回傳深複本，畫面加入獎勵或招募分支時不會污染原始台詞。
- `adventure.gd`：執行關卡、通關判定、解鎖計算、存檔與地圖。既有 `STAGES`、`CHAPTERS` 為資料檔的別名；不再另存一份獎勵表。
- `road_toll_story.gd`：只讀資料並顯示對話，不再反向載入冒險控制器。移除控制器對未使用舊木橋劇情實例的預載。

## 關卡欄位

固定 `id` 同時用於存檔和劇情關聯，不要為了改顯示名稱而改 ID。順序由 `STAGES` 決定；名稱、牌組順序、獎勵順序和數值均保留。

`opening` 決定是否使用農田開場與首次招募；`dialogue` 決定戰前／戰後對話；`enemy_camp` 決定是否撤去敵方常駐經濟建築；`enemy_lord_active` 決定敵方領主是否參戰。這些行為不再依賴「第 1／3／9 關」的條件。

`deck` 是固定八張牌，或 `"player"` 表示已解鎖的自選牌組；`enemy_deck` 是正式八張敵牌，可重複。`rewards` 直接存於每關。`buildings` 保持 `[欄, 路, 正式卡牌 ID]`。舊存檔格式與 ID 不變，不需要清除進度。

## 驗證與擴充

新增或修改內容後跑 `tools/quick_test.gd`，現在也會檢查 `Catalog.validate()`：重複 ID、未知卡牌或領主、不合法牌組、重複獎勵、無效路徑、建築放在關閉路徑或相同格子等。

`tools/test_campaign_catalog.gd` 檢查劇情對應、資料深複製與錯誤案例；`tools/test_campaign_restructure.gd` 驗證完整十關流程及存檔。這次另外以重構前快照核對每一個原有關卡欄位、獎勵與兩條招募分支台詞完全相同，並比對既有八場黃金對局，沒有重錄結果。

卡牌數值依舊以 `balance.gd` 為唯一來源；本次沒有移動它，以維持現有調費工具的讀寫相容性。沒有修改戰鬥數值、台詞、UI 版面或玩家存檔。

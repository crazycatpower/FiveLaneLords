# 新增卡牌／領主指南

數值與欄位以 `balance.gd`、`B.validate()` 及現有同類卡牌為準。不要從歷史企劃複製舊費用或卡牌數量。

## 卡牌

1. 在 `CARDS` 加入資料：名稱、定位、類型、陣營、費用、冷卻及該類必填欄位。軍團沿用 `members`，召喚專用單位標記 `summon_only`。
2. 生命、傷害、射程、速度、攻擊間隔與範圍使用 [數值檔次](數值檔次.md)。優先沿用行為欄位及 AI 標籤，不在程式散落卡牌名稱判斷。
3. `card_description()` 由資料產生說明；特殊效果文字也從資料取數字。補上 `card_lore.gd` 趣聞與圖鑑內容。
4. 只有新機制才新增戰鬥處理，依建築更新、部隊更新、攻擊、傷害／死亡、法術或技能找到對應入口；出牌限制統一放 `play_check()`。
5. 檢查 `enemy_ai.gd` 的出牌評分與特殊放置策略；新牌必須能由正常出牌流程使用。
6. 按 [美術驗收](美術驗收.md) 準備原圖、prompt、隊色衍生圖；檢視兩方實際尺寸與動畫。
7. 遊戲文字新增中文字時，執行 `python tools/build_font.py` 並重新匯入。
8. 跑新機制專用測試，必要時跑 `tools/quick_test.gd`。全量回歸、黃金對局重錄及長批次平衡實驗依根目錄 `AGENTS.md`，不逐張自動跑千場。

## 領主

- 在 `LORDS` 加資料，確認陣營、常駐牌、技能費用與說明；避免假設所有領主同費用或同生命。
- 接入 `cast_skill()`、`skill_error()`、AI `skill_plan()` 與技能特效。
- 加入對應立繪，檢查牌組選擇、圖鑑、戰場、死亡與技能畫面；不要按舊版四領主版面推算。
- 專用測試涵蓋費用、冷卻、可施放條件、雙方朝向與技能結束後的狀態恢復。

更新企劃版本紀錄，只提交本項變更。量測時使用固定版本並記錄種子、牌組、樣本數與限制；`autobalance.py` 若只量測，必須加 `--dry-run`。

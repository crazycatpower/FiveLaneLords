# 新增卡牌／領主指南

> 給之後新增內容的人（Claude、Codex 或製作人）。照順序做；每一步做完都可以跑測試確認。
> 快速開發驗證：`godot_console --headless --path . -s tools/quick_test.gd`（1.5 秒核心 248 項）。
> 完整發布回歸：`godot_console --headless --path . -s smoke_test.gd`（873 項）。

## 新增一張卡牌

### 1. 在 `balance.gd` 的 `CARDS` 加一筆（大部分的牌只要這一步）

必填欄位：`name`、`role`（卡面上的小字）、`type`（`unit`／`building`／`spell`）、`cost`（1–30）、`cooldown`（0–30 秒）。依類型另外需要：

| 類型 | 必填 |
|---|---|
| unit | `count`、`hp`、`damage`、`interval`、`range`、`speed`；或用 `members` 組成軍團（再加 `art` 列出要畫的兩種兵） |
| building | `hp`、`expires`（-1＝永久） |
| spell | `radius`，有傷害的加 `damage`／`building_damage`／`gate_damage` |

部隊的 `hp`、`damage`、`interval`、`range`、`speed` 必須是 `B.TIERS` 的 SSS–G 十檔值（每檔的用途備註見 `docs/數值檔次.md`；一般部隊牌最高到 S）。範圍型的數值另有兩張檔次表：

- **範圍**（`radius`、`spread_radius`，任何類型的牌）：`B.TIERS.radius` 760／470／290／210／150／100／75／52／37／26 px，S 約蓋住 5×5 格。
- **範圍傷害**（法術的 `damage`、`building_damage`、`gate_damage`，以及 `tick_damage`、`explosion_damage`）：`B.TIERS.area_damage` 2400／1200／600／370／230／140／90／55／35／20。

不確定時，挑一個檔次，從 `TIERS` 抄數字。

**行為欄位**（寫上就生效，戰鬥程式不用改）：

| 欄位 | 效果 | 例子 |
|---|---|---|
| `"projectile": true` | 射箭，有飛行時間 | 獵戶、死靈法師 |
| `"hits": "buildings"` | 不打部隊和領主，只打建築與城門 | 攻城槌、烏鴉群 |
| `"prefers": "farm"` | 先找本路的敵方農田 | 烏鴉群 |
| `"target_rule": "lowest_serial"` | 打射程內序號最低的，不打最近的 | （目前沒有牌用） |
| `"splash": "column"` | 每次攻擊也打中目標那一欄、本路與上下相鄰兩路的敵兵 | 收割者 |
| `"flying": true` | 近戰部隊和建築打不到 | 烏鴉群 |
| `"on_death_spawn": ["skeleton",4]` | 死亡結算後原地產生指定部隊；新序號、不繼承詛咒 | 腐屍巨人 |
| `"armor": 10` | 每次正傷害減指定值，最低仍為 1 | 盾衛 |
| `"inspire_duration": 3.0` | 登場與每隔 `inspire_period: 10.0` 全場友軍移速攻速升一檔 3 秒（鼓手自身不加速） | 戰鼓手 |
| `"spread": true` | 相鄰三路各出 `count` 隻 | 乾草叉暴民 |
| `"series": "dark"` | 黑暗紀元系列（暗色卡框） | 黑暗紀元的牌 |
| `"faction": "normal"`／`"dark"` | 陣營：只有該陣營的領主能放進牌組；不寫＝中立，所有領主都能用 | 豐收（經典）、骷髏兵（黑暗） |

**AI 標籤** `"ai": [...]`（寫上就會被 AI 用對地方，`enemy_ai.gd` 不用改）：

| 標籤 | AI 怎麼用 |
|---|---|
| `defend_spell` | 敵兵逼近城門時，丟在敵兵身上 |
| `wave_spell` | 進攻時，丟在敵方成群的地方 |
| `raid` | 敵方農田多的時候，送去那一路拆田 |
| `guard` | 有農田的路，早早蓋一座 |
| `defend_building` | 敵兵逼近時，蓋在敵兵前面擋路 |
| `obstacle` | 選進攻路時，當作敵方的牆（避開） |
| `no_defend` | 不拿來防守 |
| `hold` | 錢有剩才出（或金幣 45 以上，避免卡手） |

沒有標籤的部隊，AI 會在進攻時照一般方式出；沒有標籤的建築和法術，AI 只在金幣多時拿來消耗。

`B.validate()` 會檢查以上所有欄位：缺欄位、數值不在檔次上、行為欄位或標籤拼錯，測試會失敗並寫出是哪張牌、哪個欄位；開遊戲時也會印在 Godot 的錯誤輸出。

### 2. 卡牌說明

`balance.gd` 的 `card_description()` 會自動寫出費用、數值等共通內容。牌有特殊機制的話，在它最後的 `match kind:` 加一行說明，數字一律從 `CARDS` 讀。

### 3. 圖

存成 `assets/manuscript-v1/<卡牌 id>.png`，例如 `raven.png`；用 GPT 生成時，prompt 存進同資料夾的 json。測試會檢查每張牌、每位領主都有圖。藍方不用另外畫，`recolor_blue()` 會自動換色。

**部隊與領主的圖一律朝右**（面向藍方）；藍方由遊戲左右翻轉，所以原圖朝左就會整支部隊倒著走。新增或修改任何圖之後，照順序跑：

1. `godot_console --headless --path . -s tools/prepare_assets.gd`（重新產生藍方換色圖，直接讀磁碟上的原圖）
2. `godot_console --headless --path . --import`

快速測試裡的 `tools/test_art_palette.gd` 會檢查每張藍方圖都由目前的原圖產生、輪廓方向一致；忘了重產會直接失敗。

### 4. 只有真正獨特的機制才改程式

`battle.gd` 的 `step()` 依序呼叫各階段，照機制類型找對應的函式：

| 機制 | 改這裡 |
|---|---|
| 建築定時產出或攻擊 | `update_buildings()` |
| 部隊每一步的特殊行為（召喚、光環…） | `update_unit()`（參考 `summon_skeletons()`） |
| 部隊選目標 | `choose_target()`（先看能不能用行為欄位做到） |
| 攻擊時的特殊效果 | `attack()` |
| 單位死亡時觸發 | `damage()` 歸零處＋`resolve_deaths()`（墓碑、食屍鬼的寫法） |
| 法術效果 | `cast_spell()` |
| 出牌限制 | `play_check()`（規則只有這一份；`can_play()`、`play_error()` 都讀它） |

AI 要特別的放法時，在 `enemy_ai.gd` 的 `dark_card_score()` 加一個 `match` 分支（照黑暗紀元的牌寫）。

### 5. 字型

有新的中文字：`python tools/build_font.py`，再 `godot_console --headless --path . --import`。

### 6. 測試與黃金對局

1. 在 `smoke_test.gd`（或像 `tools/test_dark_age.gd` 那樣另開一個檔，再從 `smoke_test.gd` 的 `run()` 呼叫）為獨特機制加 `check()`，數值從 `B.CARDS` 讀。
2. 跑測試。**加新牌一定會讓黃金對局（`golden match seed …`）失敗**：隨機牌組會抽到新牌，對局結果跟著變。這是預期的，確認其他測試都過之後，執行 `godot_console --headless --path . -s tools/make_golden.gd` 重錄，再跑一次測試。
3. 只改程式結構、沒有要改玩法時，黃金對局**不可以**失敗；失敗就代表行為被改到了。

### 7. 平衡與紀錄

- 跑一次 `python tools/autobalance.py --total 1000 --rounds 1 --dry-run`（約 8 分鐘），看新牌的勝率、每金幣傷害，結果給製作人看。
- 在 `docs/企劃書.md` 最上方的版本紀錄加一條，一個改動一個 commit。

## 新增一位領主

1. `balance.gd` 的 `LORDS` 加一筆（必填 `faction`：`normal` 或 `dark`；常駐牌不是農田時加 `home_card`，它必須是同陣營的建築）：`name`、`role`、`hp`、`damage`、`speed`（SSS–G 檔次值）、`skill`、`skill_desc`；技能費用不是 50 時加 `skill_cost`。
2. 技能效果寫在 `battle.gd` 的 `cast_skill()` 的 `match kind:`；不能發動的條件寫在 `skill_error()`。
3. AI 什麼時候放技能，寫在 `enemy_ai.gd` 的 `skill_plan()`。
4. 技能特效在 `game.gd` 的 `draw_skill_effect()`。
5. 圖存成 `assets/manuscript-v1/lord-<領主 id>.png`。
6. 牌組畫面的領主格是 2×2（`lord_rect()`），第 5 位以上要調整版面。
7. 之後照上面第 5–7 步：字型、測試、黃金對局、平衡。

## 3. 工作流程（每次改動都要做）

1. 改 `balance.gd` 的數值，不要把數字寫死在函式裡。
2. 跑測試：`godot_console --headless --path . -s smoke_test.gd`，**回傳 0 才算完成**。
3. 新規則要在 `smoke_test.gd` 用 `check(條件, "說明")` 加測試；測試要從 `B.CARDS` 等常數讀數值，不要寫死。
4. 有改到畫面：不加 `--headless` 再跑一次測試，會重拍 `preview.png`、`title-preview.png`、`deck-preview.png`，**打開看過**再交。
5. 有新增中文字：`python tools/build_font.py`，再跑一次 `godot_console --headless --path . --import`，否則新字會退回系統字型。
6. 動到平衡：跑**一次** `godot_console --headless --path . -s tools/sim.gd -- --games=3`（約 2 分鐘，18 局），把勝率、平手局、浪費金幣列給製作人。**不要反覆跑長批次自己調數字**，製作人明確不喜歡；給選項讓製作人決定。
7. 每個改動一個 git commit，訊息寫清楚改了什麼、為什麼（附上模擬前後數字）。

## 4. 已知陷阱

- **測試裡換手牌後要把冷卻歸零**：`m.hand_cd[team] = [0.0,0.0,0.0,0.0]`；常駐農田是 `m.farm_cd[team]`。不然新換進來的牌在冷卻中，出牌會失敗。
- **測試要空棋盤就用 `bare()`**（會清掉開局的兩塊田）；要測開局狀態才用 `Battle.new()`。
- **常駐農田不在輪轉牌組裡**：要取某格的牌用 `kind_at(team, slot)`，不要直接讀 `decks[team][slot]`（AI 曾因此一張田都出不了）。
- **typed 陣列**不能整個用一般陣列指派，要逐格改。
- **新函式名別撞 Godot 內建**（例如 `draw_ellipse`）。
- 腳本出錯時測試會停在那一段；`run()` 結尾的 `finished` 檢查會把這種情況算成失敗，新增測試段落時照同樣方式加。
- 製作人的 Godot 4.7.2 編輯器常開著，可能會改寫 `project.godot`（例如省略預設值）；不影響功能。
- 美術：雙方共用一套圖，藍方由 `recolor_blue()` 把紅色換藍，**不要整張染色**；新素材的 prompt 存進 `assets/manuscript-v1/` 的 json/txt。
